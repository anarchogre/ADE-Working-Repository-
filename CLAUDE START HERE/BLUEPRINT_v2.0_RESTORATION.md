# BLUEPRINT_v2.0_RESTORATION.md

This file intentionally preserves the existing Blueprint as the engineering baseline while changing project execution strategy.

## Canonical Rules

- Existing Blueprint remains the architectural baseline.
- Repository restoration takes precedence over optimization.
- New artifacts supersede old artifacts by version, never by overwrite.
- GitHub is canonical until replaced by newer approved artifacts.
- Complete state snapshots are generated at major milestones.
- Chat bootstrap packages must contain sufficient context to resume work without relying on chat history.

## Baseline

The complete v0.1 Blueprint reviewed during this session remains the technical baseline and is to be validated against the repository before modification.
